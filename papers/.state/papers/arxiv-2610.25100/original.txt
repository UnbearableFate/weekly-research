                                           Abstract Large language models need effective ways to acquire and use external knowledge beyond
                                           what they retain from pretraining. Continued pretraining risks catastrophic forgetting, while retrieval at
                                           inference time can add substantial overhead. External parametric memory avoids online retrieval, but
                                           constructing its training data requires extensive offline search, and output-level interpolation provides
                                           only shallow fusion. We introduce Deep Fusion Memory (DFM), a parametric memory architecture that
                                           reduces this construction workload and incorporates learned memory into intermediate hidden states. A
                                           causal memory predictor learns to generate memory from the preceding context, using retrieved chunk
                                           embeddings from the corpus as supervision. The predicted memory is shared across tokens within each
                                           chunk and fused into their hidden states through gated cross-attention. Memory prediction and fusion
                                           are trained end to end with the backbone frozen, and inference requires no explicit retrieval. Compared
                                           with existing parametric memory approaches, which often construct token-level memory targets, DFM
                                           requires 32× fewer retrieval queries and 2048× fewer retrieved items to construct its training data.
                                           Across six QA tasks, DFM performs better over the strongest baseline by 12.71% on Mistral-7B-v0.3 and
                                           11.19% on Qwen3-8B-Base. Beyond QA, domain adaptation yields average gains of 6.51 and 4.38 points
                                           over Qwen3-4B-Base and Qwen3-8B-Base, respectively. The code will be released soon.



                                         1. Introduction
                                         Large language models (LLMs) (Yang et al., 2025; Liu et al., 2025; Team et al., 2025; Bai et al., 2026)
                                         have advanced rapidly in language understanding, generation, and reasoning. Their growing capabili-
                                         ties support knowledge-intensive applications, but reliable answers require facts that can be missing,
                                         poorly retained, or outdated in pretrained parameters (Lewis et al., 2020). Knowledge injection
                                         addresses this gap by incorporating information from an external corpus. A central challenge is to
                                         incorporate this knowledge effectively while preserving existing capabilities and keeping knowledge
                                         acquisition and inference costs manageable.
                                         Existing approaches face different trade-offs in addressing this challenge. Continued pretraining
                                         (CPT) (Gururangan et al., 2020) learns from an additional corpus through language modeling, while
                                         LoRA (Hu et al., 2021) offers a parameter-efficient way to adapt the model. These approaches keep
                                         inference self-contained, but adaptation can cause catastrophic forgetting of previously acquired
                                         capabilities (Biderman et al., 2024). Non-parametric retrieval instead provides external evidence
                                         during generation. RAG (Lewis et al., 2020) conditions on retrieved passages, and RETRO (Borgeaud
                                         et al., 2022) incorporates retrieved chunks within the decoder. These methods provide access to
                                         corpus knowledge without first learning it in model parameters, but datastore search and evidence
                                         processing can add substantial inference latency (Cao et al., 2026).
                                      Deep Fusion Memory

Parametric memory learns from retrieved knowledge offline, enabling inference without explicit
retrieval. MLP Memory (Wei et al., 2026a) and Memory Decoder (Cao et al., 2026) learn to predict
retrieval-derived next-token distributions. However, this inference advantage comes with substantial
offline costs. Constructing token-level training targets requires retrieval at individual token positions
across the corpus, resulting in substantial data construction costs (Wei et al., 2026b). Training memory
modules on these targets further incurs significant computational cost. Moreover, these methods
rely on shallow fusion through output-probability interpolation, without incorporating memory into
the decoder’s hidden states. Intuitively, integrating memory into intermediate hidden states allows
subsequent layers to further process and combine it with the evolving context. The broader challenge
is to enable language models to acquire external knowledge efficiently and use it effectively.
In this work, we introduce Deep Fusion Memory (DFM), a parametric memory architecture that
combines efficient knowledge acquisition with deep fusion within the decoder (Figure 1). At a high
level, DFM shares memory supervision across multiple token predictions while allowing each token to
use the learned memory according to its context. We jointly train a memory predictor and a memory
fusion module, using retrieved target memory to supervise the predictor and the standard language
modeling objective to train both modules. In this way, external knowledge is not only stored in the
predictor’s parameters, but also injected into intermediate hidden states through the fusion module,
allowing subsequent decoder layers to utilize the memory during generation. The LLM backbone
remains frozen throughout, and memory prediction is performed at the chunk level.
Our experiments demonstrate improvements in both efficiency and downstream performance. Com-
pared with existing parametric memory approaches that construct token-level memory targets, DFM
requires 32× fewer retrieval queries and 2048× fewer retrieved items to construct its training data.
DFM achieves the highest average score across six QA tasks on both backbones, outperforming
the strongest baseline by 12.71% on Mistral-7B-v0.3 and 11.19% on Qwen3-8B-Base. Beyond QA,
adaptation across code, mathematics, and law yields average gains of 6.51 and 4.38 points over
Qwen3-4B-Base and Qwen3-8B-Base, respectively. Ablations further highlight the importance of
fusion placement and gate initialization, while showing comparatively small changes in average QA
performance across the tested chunk sizes and numbers of memory slots.
Our contributions are summarized as follows:
• We introduce DFM, a parametric memory architecture with deep fusion, which integrates
  learned corpus knowledge into intermediate hidden states so that subsequent decoder layers can
  process memory together with the evolving context. Inference requires no explicit retrieval.
• We reduce the overhead of supervision construction and memory training through chunk-level
  supervision and end-to-end training with a frozen backbone. For training data construction, DFM
  requires 32× fewer retrieval queries and 2048× fewer retrieved items than existing parametric
  memory approaches based on token-level targets.
• We demonstrate improved QA performance and domain adaptation. Across six QA tasks, DFM
  performs better over the strongest baseline by 12.71% on Mistral-7B-v0.3 and 11.19% on Qwen3-8B-
  Base. Across code, mathematics, and law, average gains over Qwen3-4B-Base and Qwen3-8B-Base
  reach 6.51 and 4.38 points, respectively.


2. Related Work
Model Adaptation. Continued pretraining adapts language models to additional corpora through
further language modeling (Gururangan et al., 2020), while LoRA (Hu et al., 2021) offers a parameter-
efficient way to adapt the model. Such adaptation can cause catastrophic forgetting of previously
acquired capabilities (Biderman et al., 2024). Deep Fusion Memory keeps the backbone frozen and

learns an added memory module from retrieval-derived targets, jointly training memory prediction
and fusion.
Retrieval-Augmented Language Models. Non-parametric memory exposes corpus information
through several interfaces. 𝑘NN-LM retrieves context–token pairs and interpolates a neighbor-derived
next-token distribution with the language model output (Khandelwal et al., 2019), whereas RAG
conditions generation on retrieved passages (Lewis et al., 2020). RETRO combines chunk retrieval
with cross-attention inside the Transformer (Borgeaud et al., 2022). xRAG projects a retrieved
document embedding into a single token representation prepended to the query, reducing the context
passed to the generator (Cheng et al., 2024). These methods retain an external retrieval dependency
at inference. Deep Fusion Memory predicts continuous memory parametrically and uses it inside the
decoder without online search.
Parametric Memory. MLP Memory trains an MLP to predict 𝑘NN token distributions from language
model representations (Wei et al., 2026a). Memory Decoder learns a similar distributional target
with a standalone decoder (Cao et al., 2026). Memory Decoder at Scale extends this approach to
large-scale general and domain memory pretraining (Wei et al., 2026b). MemSFT specializes frozen
backbones through a domain memory and a learned token-wise router over the backbone and memory
output distributions (Wang et al., 2026). These approaches avoid explicit retrieval at inference, but
token-level retrieval incurs substantial data construction costs, and output-probability interpolation
provides only shallow fusion. Deep Fusion Memory reduces the cost of supervision construction by
sharing target memory across tokens within each chunk and fuses predicted memory into hidden
states through gated cross-attention.


3. Deep Fusion Memory
Deep Fusion Memory consists of a causal chunk-level memory predictor and memory cross-attention
modules inserted into selected decoder layers (Figure 1). We construct target memory offline, then
jointly train the added modules with language-modeling and memory-prediction objectives while
keeping the backbone frozen. At inference, the predictor supplies memory directly from the input
sequence.


3.1. Training data construction

We partition each training sequence into non-overlapping chunks 𝑋0 , . . . , 𝑋 𝐽 −1 of 𝐶 tokens. For each
chunk 𝑋 𝑗 with 𝑗 ≥ 1, an offline retriever encodes the preceding chunk 𝑋 𝑗 −1 and retrieves its top- 𝐾
neighbors from a corpus datastore. Each retrieved chunk is represented by a fixed dense embedding
produced by a frozen text encoder. Stacking these embeddings in retrieval-rank order gives the target
memory 𝑉 𝑗 ∈ ℝ 𝐾 × 𝑑𝑚 , where 𝑑𝑚 is the embedding dimension. This ordering aligns the target memory
with the predictor’s output slots.
Each training example pairs the original token sequence with its chunk-level target memory. Each
target memory supervises the predictor output shared across token predictions in 𝑋 𝑗 . Predictions for
the first chunk use no memory, and this chunk is excluded from memory supervision because it has no
preceding-chunk query. Target memory is prepared offline and remains fixed during model training.

3.3. Inference

At inference, the language model uses the same predictor and fusion modules without constructing
target memory. Chunk queries are formed from backbone input embeddings, and the memory
predictor supplies predicted memory to the selected decoder layers. No datastore search, retrieved
text, or external embedding encoder is required. For QA evaluation, predicted memory is computed
from the visible prompt and remains fixed during answer generation. Selected decoder layers attend
to the predicted memory only at positions associated with the prompt chunks. As defined in Eq. 2, a
sigmoid gate conditioned on the current token state scales each head before output projection. With
layer-specific gate parameters, the contribution of the fixed memory can vary across tokens, heads,
and layers.

4.1. Experimental Setup

Datasets. For question answering, we train on English Wikipedia from December 2018, comprising
approximately 4B tokens. We evaluate single-hop QA on NQ (Kwiatkowski et al., 2019) and We-
bQA (Berant et al., 2013), and multi-hop QA on HotpotQA (Yang et al., 2018), 2WikiMultiHopQA (Ho
et al., 2020), MuSiQue (Trivedi et al., 2022), and Bamboogle (Press et al., 2023). For domain adapta-
tion, we sample subsets from Swallow-Code (Fujii et al., 2026) and Swallow-Math (Fujii et al., 2026),
and use legal text from DISC-Law-SFT (Yue et al., 2023). We evaluate Code on HumanEval (Chen
et al., 2021) and HumanEval+ (Liu et al., 2023), Math on GSM8K (Cobbe et al., 2021), and Law on
LawBench (Fei et al., 2024). Appendices A.1 and A.2 give data-construction and evaluation details
for QA and domain adaptation.
Training Details. We use Mistral-7B-v0.3 (Jiang et al., 2023) and Qwen3-8B-Base (Yang et al., 2025)
for question answering, and Qwen3-4B-Base and Qwen3-8B-Base (Yang et al., 2025) for domain
adaptation. DFM uses 32-token chunks and target memory formed from the top-16 chunk embeddings
retrieved using Qwen3-Embedding-0.6B (Zhang et al., 2025), with gated memory fusion at layers
[9, 16, 24, 31]. The added modules contain 0.75B parameters on both QA backbones and 0.6B on
Qwen3-4B-Base. We freeze the backbone and train the added modules for one epoch with next-token
cross-entropy and memory-prediction MSE, using AdamW with learning rate 1 × 10−5 . Wikipedia
training uses 2,048-token sequences and a global batch size of 128 on 16 A800 80GB GPUs. For
domain adaptation, we train a separate model for each domain with 262,144 tokens per optimizer
update. Further architectural details and training configurations are given in Appendix A.
Baselines. We compare against three non-parametric and three parametric baselines. Among non-
parametric methods, RAG (Lewis et al., 2020) augments the input with the top-1 passage retrieved
using Qwen3-Embedding-0.6B. xRAG (Cheng et al., 2024) projects a retrieved document’s dense
embedding into a single token prepended to the question. RETRO (Borgeaud et al., 2022) incorporates
retrieved chunks through cross-attention. Among parametric methods, CPT updates all backbone
parameters through continued pretraining for one epoch. LoRA (Hu et al., 2021) trains low-rank
adapters for one epoch, with its added parameter budget matched to DFM. MLP Memory (Wei et al.,
2026a) learns to predict token-level kNN distributions from Wikipedia 2018 and interpolates its
predictions with the backbone’s output probabilities.

6. Conclusion
We presented Deep Fusion Memory (DFM), a parametric memory architecture that combines efficient
supervision construction with deep fusion within the decoder. Sharing target memory across tokens
in each chunk reduces retrieval work, while gated cross-attention allows subsequent decoder layers
to process predicted memory together with the evolving context. Memory prediction and fusion
are trained end to end with the backbone frozen, and inference requires no explicit retrieval. DFM
improves the six-task QA average over the strongest baseline by 12.71% on Mistral-7B-v0.3 and
11.19% on Qwen3-8B-Base. Beyond QA, DFM improves performance over the base models across
code, mathematics, and law. These results demonstrate that shared supervision and learned internal
fusion can support efficient knowledge acquisition and effective memory use.

A. Experimental Details

A.1. Question Answering

Data construction. We use section and infobox text from Wikipedia December 2018. Records are
grouped by normalized article titles and assigned to training, validation, and test splits in proportions
of 99.8/0.1/0.1% using seed 42. We remove exact text duplicates across splits, append EOS to each
record, and pack records within each split into 2,048-token sequences. Incomplete final sequences
are discarded. Tokenization yields 4.70B, 4.29B, and 4.08B training tokens for Mistral, Qwen3, and
OLMo3, respectively. Each sequence is divided into non-overlapping 32-token chunks. We encode
training chunks with the frozen Qwen3-Embedding-0.6B encoder, using last-token pooling and L2
normalization to obtain 1,024-dimensional representations. A FAISS IVF-PQ index supports offline
neighbor retrieval. Following Section 3.1, each preceding chunk retrieves target memory for the next
chunk. We retain the top-16 full chunk embeddings in retrieval-rank order, including the nearest
neighbor, and mask the first chunk from memory supervision. The datastore contains training chunks
only.
Training. DFM freezes the backbone and jointly trains its chunk-level memory predictor, shared
projector, and gated fusion modules. The predictor has 28 layers, hidden width 1,024, FFN width 3,072,
16 query heads, and eight KV heads. Its 16 output heads predict the continuous memory slots. The L2-
normalized targets have coordinates in [−1, 1], and the predictor clips output coordinates to this range.
Memory cross-attention is inserted at zero-based layers [9, 16, 24, 31], with gate weights initialized to
zero and gate biases to −2. OLMo3 retains its original attention-output normalization. The objective
combines next-token cross-entropy and raw memory-prediction MSE with equal weights. We train
for one epoch on 16 A800 80GB GPUs, with one sequence per GPU and eight gradient-accumulation
steps, giving a global batch size of 128. AdamW uses learning rate 1 × 10−5 , ( 𝛽1 , 𝛽2 ) = (0.9, 0.999),
𝜖 = 10 −8 , zero weight decay, and gradient clipping at 1. We use 500 warmup steps followed by cosine
decay, BF16 precision, seed 42, and the final checkpoint for evaluation.
Baselines. RAG (Lewis et al., 2020) retrieves the top-1 document from a Wikipedia training-corpus
index using Qwen3-Embedding-0.6B and adds it to the question context. xRAG (Cheng et al., 2024)
projects a retrieved document’s dense embedding into a single token prepended to the question.
RETRO (Borgeaud et al., 2022) uses chunk-level retrieval and cross-attention to incorporate retrieved
text into hidden states. CPT updates all backbone parameters for one epoch on Wikipedia at learning
rate 2 × 10−5 . LoRA (Hu et al., 2021) trains low-rank adapters for one epoch at the same learning
rate of 2 × 10−5 , with the added parameter budget matched to DFM. MLP Memory (Wei et al., 2026a)
learns to predict token-level kNN distributions from Wikipedia 2018 and interpolates its predictions
with the backbone probabilities. As in MLP Memory, interpolation weights are task-specific; we select
the best 𝜆 ∈ {0, 0.05, . . . , 1} on each reported evaluation split. In the task order of Table 4, we use
𝜆 = (0.55, 0.55, 0.55, 1.00, 0.90, 1.00) for Mistral and (0.35, 0.45, 0.25, 0.80, 0.55, 0.00) for Qwen3.

Evaluation. Table 4 summarizes the six QA benchmarks. DFM uses zero-shot greedy decoding without
online retrieval, gold documents, or chain-of-thought demonstrations. Questions are formatted with
task-specific question–answer templates. Generation stops at a newline or the token limit, with period
and comma as additional stop strings for WebQA. Evaluation batches contain one example per GPU,
except WebQA, which uses four. For QA, each memory query is formed from the current visible prompt
chunk rather than the preceding chunk used during training. The queries and predicted memory
remain fixed during generation. For newly added chunk positions, the adapter pads queries and
query-validity masks with zeros, so these positions receive no direct memory update. Generated
answer chunks do not refresh the queries, and incremental predictor caching is not used in the
reported implementation. F1 measures normalized token overlap and takes the maximum over

Data. Code and Math each use 100M training tokens sampled from Swallow-Code and Swallow-

512, and zero dropout. We train a separate checkpoint for each domain.
RAG. RAG uses the frozen Base backbone without additional training. It retrieves the top-1 document

examples, sample counts, generation settings, and scorers are identical to Base.
Evaluation. HumanEval uses three demonstrations and four samples per problem, while HumanEval+
uses zero demonstrations and one sample. Code reports sample-average execution correctness,
estimating pass@1. GSM8K uses eight demonstrations and one sample. LawBench evaluates 500
examples for each of its 20 tasks in the zero-shot setting. All methods use a common Input:/Output:
